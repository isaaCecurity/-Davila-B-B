| TD-013 | **Trigger functions and helpers are exposed as callable RPCs, five of them to `anon`.** Supabase security advisors, run 2026-08-11: `prevent_submitted_ticket_update()`, `bump_cash_session_revision()` and `guard_daily_financial_audit_mutation()` are *trigger* functions with no business being reachable at `/rest/v1/rpc/…` at all, yet are `SECURITY DEFINER` and EXECUTE-able by `anon`. `archive_ticket(uuid,text)` and `has_permission(text,uuid)` are likewise anon-executable. | TD-012 | **`docs/API-CONTRACT.md` §4 is wrong about money transport.** It states "Money arrives as a string. PostgREST serialises NUMERIC as a string." PostgreSQL renders `numeric` **unquoted** in JSON, so `JSON.parse` in `supabase-js` yields a JS double and the declared scale is destroyed before application code runs. Executed live: `row_to_json` of `184500.0000::numeric(19,4)` arrives as `184500`; `::text` yields `'184500.0000'`. The SQL suite's C7b shows `12345678901234.5678` becoming `12345678901234.6` through a double. | Any code trusting §4 silently corrupts money. The P4.1a read service works around it by casting every numeric column with `::text` and having Zod reject a JSON number in those positions. | `tests/sql/catalog_read_rls.sql` C7a/C7b/C7c — executed, passed. §4 should be corrected. |
